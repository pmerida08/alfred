# Notas — 2026-05-11

## Sesión: Sincronización servidor + despliegue 24/7

### Contexto
Pablo quería tener el proyecto Alfred sincronizado automáticamente entre su PC Windows y su servidor Linux Mint, y que el bot de Telegram estuviera disponible 24/7 sin intervención manual.

### Decisiones tomadas
- Se eligió **Syncthing** para la sincronización (ya lo usaba para Obsidian).
- El directorio local es `D:\Programas\Alfred`, en el servidor `/home/pablo/Documentos/Alfred` (con A mayúscula — importante).
- Syncthing en el servidor corre como servicio de usuario con `loginctl enable-linger pablo`.
- Se descartó git+hooks y rsync por ser menos transparentes para el flujo de trabajo.

### Infraestructura desplegada en el servidor

- **alfred.service** (systemd user): arranca Claude en sesión tmux `alfred` al encender el servidor. Para acceder: `tmux attach -t alfred`.
- **alfred-telegram.service** (systemd user): corre `execution/telegram_bot.py` en background, se reinicia automáticamente si cae.
- Ambos servicios habilitados con `systemctl --user enable` + `loginctl enable-linger`.

### Errores encontrados y soluciones

| Error | Causa | Solución |
|-------|-------|----------|
| `No such file or directory: '/home/pablo/Documentos/alfred'` | Ruta con minúscula en telegram_bot.py | La ruta es `Alfred` con mayúscula; `PROJECT_ROOT` se calcula dinámicamente así que se resolvió solo |
| `status=203/EXEC` en alfred.service | `tmux` no instalado + ExecStop sin ruta absoluta | `sudo apt install tmux` + eliminar ExecStop del servicio |
| alfred_start.sh no encontrado | Ruta hardcodeada con `alfred` minúscula | Corregido a `Alfred` en setup_server.sh y alfred_start.sh |
| claude.exe path en Windows en telegram_bot.py | Bot apuntaba a ruta Windows | Añadida detección de plataforma; en Linux usa `/home/pablo/.nvm/versions/node/v20.20.2/bin/claude` |

### Rutas clave del servidor
- Claude CLI: `/home/pablo/.nvm/versions/node/v20.20.2/bin/claude`
- Virtualenv: `/home/pablo/alfred-venv`
- Proyecto: `/home/pablo/Documentos/Alfred`

- Logs alfred: `journalctl --user -u alfred -f`
